# Arvix — персональный тренажёрный помощник

Дата: 2026-07-29
Статус: на утверждении

## 1. Что это

Офлайн-сайт для одного пользователя, который открывается с телефона в зале и отвечает на три вопроса по каждому упражнению: **что делать**, **как это делать правильно** и **сколько**. По ходу тренировки отмечаются выполненные подходы, а сайт сам считает, когда пора увеличить рабочий вес.

Это не соцсеть, не маркетплейс программ и не приложение с аккаунтами. Один пользователь, одна программа, никакой регистрации и никакого сервера.

## 2. Контекст использования

Пользователь тренируется три раза в неделю по своей системе Full Body (вторник, четверг, воскресенье). В зале телефон в потной руке, интернета может не быть, времени вчитываться — тоже. Отсюда три жёстких требования:

- **Работает без сети.** После первого захода всё лежит в кеше телефона, включая анимации.
- **Один тап на действие.** Закрыть подход — один тап, не форма из трёх полей.
- **Крупные элементы.** Всё нажимается большим пальцем без прицеливания.

## 3. Границы

**Входит в v1:**

- Три дня программы с силовым блоком и атлетическим финишером
- Карточка техники на каждое упражнение: анимация, шаги, частые ошибки, целевые мышцы
- Отметка подходов, поле рабочего веса, подсказка «в прошлый раз: 60 кг»
- Таймер отдыха с автозапуском и вибрацией
- Расчёт двойной прогрессии и подсказка «пора добавить вес»
- Установка иконкой на главный экран, полная работа офлайн

**Не входит в v1** (осознанно, чтобы v1 доехал до зала быстро; каждый пункт добавляется потом за вечер):

- Разгрузочная неделя — переключатель, срезающий объём на 40–50%
- Экспорт дневника текстом для последующего анализа в чате
- История тренировок и графики прогресса
- Синхронизация между устройствами

## 4. Архитектура

Vite + React, сборка в чистую статику, деплой на бесплатный хостинг. Никакого бэкенда и никакой базы — весь прогресс живёт в `localStorage` телефона.

```
arvix/
├── public/
│   ├── gifs/                    анимации упражнений, по одной на упражнение
│   ├── icons/                   иконки для установки на главный экран
│   └── manifest.webmanifest
├── src/
│   ├── data/
│   │   ├── exercises.json       библиотека: КАК делать
│   │   └── program.json         программа: ЧТО и СКОЛЬКО делать
│   ├── components/
│   │   ├── DayList.jsx          главный экран, три дня
│   │   ├── WorkoutScreen.jsx    экран тренировки
│   │   ├── ExerciseRow.jsx      строка упражнения: гифка, параметры, подходы
│   │   ├── SetTracker.jsx       ряд кружков-подходов
│   │   ├── ExerciseDetail.jsx   развёрнутая карточка техники
│   │   ├── AthleticBlock.jsx    финишер, другая вёрстка
│   │   └── RestTimer.jsx        таймер отдыха
│   ├── lib/
│   │   ├── progression.js       правило двойной прогрессии (чистые функции)
│   │   ├── storage.js           чтение/запись localStorage
│   │   └── router.js            минимальный хеш-роутинг, без библиотеки
│   ├── hooks/useWorkout.js      состояние текущей тренировки
│   └── App.jsx
└── vite.config.js               + vite-plugin-pwa
```

**Почему два JSON, а не один.** Техника жима лёжа описывается один раз, даже если жим встречается в двух днях. Меняется программа — правится только `program.json`, справочник не трогается. Меняется описание техники — программа не трогается.

**Почему хеш-роутинг.** Три экрана можно держать на состоянии, но тогда системная кнопка «назад» на телефоне выкинет из приложения вместо возврата к списку дней. Хеш-роутинг на 30 строк решает это без зависимости.

## 5. Модель данных

### 5.1 `exercises.json` — библиотека

Ключ — идентификатор упражнения, он же имя файла гифки.

```json
{
  "back-squat": {
    "name": "Приседания со штангой",
    "equipment": "Штанга, стойки",
    "primary": ["Квадрицепс", "Ягодичные"],
    "secondary": ["Бицепс бедра", "Разгибатели спины"],
    "steps": [
      "Штанга на верхе трапеций, хват чуть шире плеч, локти под грифом.",
      "Стопы на ширине плеч, носки развёрнуты на 15–30°.",
      "Вдох, задержка дыхания, напряги пресс — рёбра вниз.",
      "Садись, разводя колени в стороны по линии стоп, до параллели бедра с полом.",
      "Встань, отталкиваясь всей стопой, выдох в верхней точке."
    ],
    "mistakes": [
      "Колени сводятся внутрь",
      "Круглится поясница в нижней точке",
      "Отрыв пяток от пола"
    ],
    "tip": "Если пятки отрываются — не хватает подвижности голеностопа, подложи блины под пятки или возьми штангетки.",
    "weightStep": 2.5
  }
}
```

`weightStep` — на сколько сайт предлагает увеличить вес при успешной двойной прогрессии. 2.5 кг для штанги и тренажёров, 2 кг для гантелей (шаг гантельного ряда), 5 кг для жима ногами.

### 5.2 `program.json` — программа

```json
{
  "title": "Full Body 3×/нед",
  "days": [
    {
      "id": "tue",
      "weekday": "Вторник",
      "accent": "Ноги",
      "blocks": [
        {
          "exercise": "back-squat",
          "sets": 3,
          "reps": [5, 8],
          "rir": 2,
          "rest": 180,
          "tempo": "2-0-1"
        }
      ],
      "athletic": [
        {
          "exercise": "medball-slam",
          "format": "3 × 8",
          "rest": 45
        }
      ]
    }
  ]
}
```

- `reps` — массив из двух чисел, нижняя и верхняя граница диапазона. Именно верхняя граница нужна для двойной прогрессии, поэтому диапазон хранится числами, а не строкой «5–8».
- `rir` — запас повторений в рабочих подходах.
- `rest` — секунды, ими же инициализируется таймер отдыха.
- `tempo` — опциональное поле, указывается только там, где темп реально важен.
- `athletic` — блок финишера. Живёт по другим правилам: там нет рабочего веса и двойной прогрессии, только формат и отдых. Поэтому отдельный массив, а не признак внутри `blocks`.

### 5.3 `localStorage`

Один ключ `arvix.v1`:

```json
{
  "version": 1,
  "lastSession": {
    "back-squat": { "weight": 80, "reps": [8, 8, 7], "date": "2026-07-21" }
  },
  "current": {
    "dayId": "tue",
    "startedAt": "2026-07-29T18:04:00.000Z",
    "reps":    { "back-squat": [8, 8, null] },
    "weights": { "back-squat": 82.5 }
  }
}
```

По каждому упражнению хранится **только последняя сессия**. Этого ровно хватает для двойной прогрессии, данные остаются крошечными, и не нужно решать, когда чистить историю. `null` в массиве `reps` — подход ещё не закрыт.

Битый или отсутствующий JSON не должен ронять приложение: при ошибке разбора состояние сбрасывается в пустое, тренировка просто начинается с чистого листа.

## 6. Программа v1 — конкретный подбор

Собрано по принципам из твоей системы: каждая тренировка Full Body, у каждой свой акцент, в основе база, изоляция только там, где её нечем заменить, минимум лишней нагрузки на поясницу.

**Это предложение, а не догма — правится до сборки.**

### Вторник — акцент ноги

| Упражнение | Подходы × повторы | RIR | Отдых | Темп |
|---|---|---|---|---|
| Приседания со штангой | 3 × 5–8 | 2 | 180 с | 2-0-1 |
| Румынская тяга с гантелями | 3 × 8–10 | 2 | 150 с | 3-0-1 |
| Жим ногами | 2 × 10–12 | 1 | 120 с | — |
| Подтягивания (или верхняя тяга) | 3 × 6–10 | 2 | 120 с | — |
| Жим гантелей лёжа | 3 × 8–10 | 2 | 120 с | — |
| Махи гантелями в стороны | 2 × 12–15 | 1 | 60 с | — |

Гантели в румынской тяге вместо штанги — сознательно: нагрузка на поясницу ниже при сопоставимом стимуле, а присед в этот день уже забирает свою долю. Жим ногами добавлен потому, что присед идёт в низком диапазоне повторений — квадрицепсу нужен объём без осевой нагрузки на позвоночник.

### Четверг — акцент грудь и спина

| Упражнение | Подходы × повторы | RIR | Отдых | Темп |
|---|---|---|---|---|
| Жим штанги лёжа | 3 × 5–8 | 2 | 180 с | 2-0-1 |
| Тяга гантели в упоре | 3 × 8–10 | 2 | 120 с | — |
| Подтягивания (или верхняя тяга) | 3 × 6–10 | 2 | 150 с | — |
| Жим гантелей на наклонной | 2 × 10–12 | 1 | 120 с | — |
| Болгарский сплит-присед | 2 × 8–10 | 2 | 120 с | — |
| Сгибание ног лёжа | 2 × 10–12 | 1 | 90 с | — |

Тяга гантели в упоре вместо тяги штанги в наклоне — по тому же принципу: упор на скамью снимает поясницу, а стимул для широчайших сопоставим. Болгарский сплит-присед закрывает ноги в день верха и попутно работает на баланс — одну из твоих целей.

### Воскресенье — акцент плечи и руки

| Упражнение | Подходы × повторы | RIR | Отдых | Темп |
|---|---|---|---|---|
| Жим гантелей сидя | 3 × 6–10 | 2 | 150 с | — |
| Жим ногами | 3 × 10–12 | 2 | 120 с | — |
| Тяга горизонтального блока | 3 × 8–10 | 2 | 120 с | — |
| Махи гантелями в стороны | 3 × 12–15 | 1 | 60 с | — |
| Сгибания на бицепс с гантелями | 2 × 10–12 | 1 | 60 с | — |
| Разгибания на трицепс на блоке | 2 × 10–12 | 1 | 60 с | — |

Жим гантелей сидя вместо жима штанги стоя — опять поясница. Если хочешь сохранить жим стоя как атлетическое движение, это ровно одна строка в `program.json`.

### Проверка частоты

| Группа | Вт | Чт | Вс | Итого |
|---|---|---|---|---|
| Квадрицепс | присед, жим ногами | болгарский | жим ногами | 3 |
| Бицепс бедра | румынская тяга | сгибание ног | — | 2 |
| Ягодичные | присед, румынская тяга | болгарский | — | 2 |
| Грудь | жим гантелей лёжа | жим лёжа, наклонный | — | 2 |
| Спина | подтягивания | тяга гантели, подтягивания | горизонтальная тяга | 3 |
| Средняя дельта | махи | — | махи | 2 |
| Бицепс | подтягивания | тяга, подтягивания | сгибания | 3 |
| Трицепс | жим гантелей | жим лёжа | разгибания | 3 |

Каждая основная группа получает минимум два раза в неделю — принцип соблюдён. Голень отдельным упражнением не выносится: её закрывает скакалка в финишере, а отдельное упражнение здесь было бы добавлением ради количества.

### Атлетический финишер

5–10 минут в конце каждой тренировки, нагрузка подобрана так, чтобы не мешать восстановлению после силовой части.

- **Вторник:** координационная лестница 3 × 30 с · медбол-слэм 3 × 8 · скакалка 3 × 45 с
- **Четверг:** баланс на BOSU 3 × 30 с на ногу · ротации с резинкой 3 × 10 на сторону · скакалка 3 × 45 с
- **Воскресенье:** свинги с гирей 3 × 12 · выпрыгивания из полуприседа 3 × 5 · скакалка 3 × 45 с

Всего библиотека v1 — 15 уникальных силовых упражнений и 7 атлетических (часть повторяется в разных днях, но описывается один раз). Итого 22 анимации.

## 7. Экраны

### Главный

Три карточки: **Вторник · Ноги**, **Четверг · Грудь и спина**, **Воскресенье · Плечи и руки**. Сегодняшний день подсвечен, остальные приглушены. Тап — переход в тренировку.

### Экран тренировки

Вертикальный список упражнений. На каждое:

- зацикленная анимация слева, название справа
- строка параметров: `3 × 5–8 · RIR 2 · отдых 3:00 · темп 2-0-1`
- поле рабочего веса с подсказкой «в прошлый раз: 80 кг»
- ряд кружков по числу подходов

**Тап по кружку** закрывает подход и проставляет внутрь верхнюю границу диапазона. **Тап по числу в закрытом кружке** открывает правку, если недобрал. То есть в хорошем случае — один тап, а данные для прогрессии всё равно собираются.

Сразу после закрытия подхода снизу выезжает **таймер отдыха**, уже с нужным временем из `rest`. В конце — вибрация. Сворачивается свайпом вниз, тренировке не мешает.

**Тап по анимации** разворачивает карточку техники: увеличенная гифка, шаги, частые ошибки, целевые мышцы, снаряд.

Ниже силовой части — **атлетический блок** на другом фоне, чтобы визуально не сливался. Карточки формата «3 × 8, отдых 45 с», отметка на упражнение целиком.

### Итог тренировки

Внизу экрана — плашка с результатами двойной прогрессии по тем упражнениям, где она сработала:

> **Жим лёжа** — все подходы на 8. В следующий раз 62.5 кг.

## 8. Правило двойной прогрессии

Точная формулировка, по ней же пишутся тесты.

Дано: последняя сессия по упражнению `{ weight: W, reps: [r₁…rₙ] }`, плановое число подходов `n`, диапазон `min–max`.

Подсказка «увеличить вес» показывается тогда и только тогда, когда:

1. записаны все `n` подходов (нет `null`), **и**
2. `min(r₁…rₙ) >= max`, **и**
3. вес текущей сессии не ниже `W` (если пользователь сознательно сбросил вес, подсказка молчит)

Предлагаемый вес: `W + weightStep`.

Подсказка ничего не навязывает и ничего не меняет автоматически — поле веса остаётся за пользователем.

## 9. Офлайн

`vite-plugin-pwa` в режиме предварительного кеширования: код, стили, оба JSON и все гифки уходят в кеш при первом заходе. Дальше сеть не нужна вообще.

`manifest.webmanifest` + иконки дают установку на главный экран и запуск в полноэкранном режиме, без адресной строки.

Гифки — обычные файлы в `public/gifs/<id>.gif`. Если файла нет, карточка показывает заглушку и не падает: это позволяет собрать работающий сайт раньше, чем найдены все анимации, и подменять их по одной.

## 10. Тестирование

Вся логика вынесена в `src/lib/` чистыми функциями — она и покрывается тестами (Vitest):

- **`progression.js`** — подсказка появляется при всех подходах на верхней границе; не появляется при одном недоборе; не появляется при неполной сессии; не появляется при снижении веса; корректный шаг веса из библиотеки.
- **`storage.js`** — запись и чтение; пустое состояние при отсутствии данных; битый JSON не роняет приложение; закрытие подхода пишет верхнюю границу диапазона.
- **`useWorkout.js`** — старт тренировки очищает `current`; правка повторов перезаписывает значение; завершение переносит `current` в `lastSession`.
- **Таймер** — отсчёт, пауза, срабатывание в нуле.

Вёрстка и поведение на телефоне проверяются вручную — автотесты на неё здесь не окупаются.

## 11. Риски

**Анимации.** Главная неопределённость. Открытые базы упражнений дают среднее качество и покрывают не всё; часть гифок придётся заменить руками. Архитектура это учитывает — гифка это файл, подменяется без правки кода.

**Программа может не подойти.** Подбор в разделе 6 сделан по принципам, но не по реальному опыту пользователя со снарядами конкретного зала. Поэтому он утверждается до сборки, а не после.
